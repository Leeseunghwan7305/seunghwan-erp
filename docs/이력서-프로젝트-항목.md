## [상세형] — 프로젝트 항목 본문

### 제조·유통 ERP + RAG 에이전트 ‘원장’ | 개인 프로젝트 (1인: 기획·백엔드·프론트·AI)
**기간**: 20XX.XX – 20XX.XX  ·  **스택**: FastAPI, SQLModel, PostgreSQL, Next.js 14(TS), TailwindCSS, Claude API, Ollama(qwen2.5:7b), bge-m3

- **RAG 챗봇을 리즈닝 에이전트로 설계** — 시스템 프롬프트에 정체성 + 5단계 사고 절차(의도 분류→근거 계획→도구 실행→자기 점검→답변)를 심어, 수동적 RAG를 스스로 도구를 고르는 에이전트로 승격
- **근거 오염 버그 근본 해결** — 웹검색 답변에 무관한 사내 문서가 근거로 붙던 문제를 **질문별 임베딩 유사도 분포 측정**(잡음 0.44 / 신호 0.52+)으로 원인 규명, 임계값을 그 사이 골(0.50)로 조정 + 화면 근거를 실제 사용 근거와 연동해 재발 차단
- **provider 중립 툴콜링 아키텍처** — ERP 도구 5종 + 웹검색을 한 벌 스키마로 정의, Claude·Ollama 포맷을 어댑터로 변환하는 ReAct 루프 구현(3-provider 라우팅)
- **할루시네이션 코드 가드** — 문서·도구 근거가 0이면 자체지식 답변을 코드에서 정형 문구로 차단(RAG_STRICT), 프롬프트로 안 잡히는 부분을 구조로 보강
- **사람 승인형 실행 에이전트** — 자연어 요청을 변경 계획으로 제안 후, 사용자 확인 시에만 등록/수정·외부 전송 실행(plan→confirm→apply), 모든 도구 호출을 감사 로그에 기록
- **RAG 파이프라인 + RBAC** — 문서 업로드→청킹→임베딩→검색(numpy 코사인)까지 구현, 역할 기반 접근 제어·로그인·출처 배지(웹/문서/ERP)로 근거 투명화
- **성과 요약** — “탄산수 재고?→라이브 도구 / 안전재고 정의?→사내 문서 / 비트코인 시세?→웹 검색”으로 근거 경로가 자동 분기하는 것을 검증, AI 답변의 **정확도·신뢰성·안전성**을 데이터 기반으로 개선
