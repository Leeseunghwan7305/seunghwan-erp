## [상세형] — 프로젝트 항목 본문 (권장)

```
[Claude/Ollama Model Routing]
Claude API와 로컬 LLM(Ollama)을 공통 인터페이스로 추상화하고, 질의 성격에 따라
모델을 라우팅(단순·고빈도 → 무료 로컬, 복잡한 추론 → Claude)하여 비용과 품질을 균형 관리.

[사내 문서 RAG 및 RAG 관리 탭 개발]
문서 업로드 → 청킹 → bge-m3 임베딩(1024차원) → PostgreSQL(JSONB) 벡터 저장 →
코사인 유사도 검색까지 RAG 파이프라인을 직접 구축. 업로드·색인 상태·검색 품질
테스트가 가능한 RAG 관리 탭 구현.

[실제 ERP 데이터를 조회/변경하는 Tool Calling Agent]
Provider에 종속되지 않는 공통 Tool Schema를 정의하고 Claude/Ollama 포맷으로 변환하는
Adapter를 구현. ReAct 루프로 재고·주문·거래처 등 실시간 업무 데이터를 안전하게 조회.

[Grounding & Hallucination Control]
검색·도구 실행 결과를 근거로 자동 주입하고, 근거가 없으면 코드 레벨에서 응답을 차단.
실시간 수치 → Tool Calling, 정적 지식 → RAG, 외부 정보 → 웹 검색으로 코드 하드코딩 없이
모델이 질의를 분류·라우팅하도록 설계해 오래된 데이터·허위 응답을 최소화.

[측정 기반 RAG 튜닝 — 근거 오염 해결]   ★ 차별 포인트
무관한 사내 문서가 근거로 딸려오던 문제를 임베딩 유사도 분포 측정(잡음 ~0.44 / 신호 0.52+)으로
진단, 자동주입 임계값을 그 사이 값(0.50)으로 캘리브레이션 + 화면 근거를 실제 사용 근거와
연동해 재발을 차단.

[실행 전 사용자 확인을 받는 Human-in-the-Loop]
자연어 요청을 구조화된 실행 계획(Plan)으로 변환 → 사용자 확인 → 입력 검증 → 실제 데이터
반영으로 단계 분리. Text-to-SQL 대신 Tool Calling 기반 실행 구조로 데이터 변경의 안전성을 확보.
```

> **작성 의도**: 6개 불릿 중 5개는 “설계·구현”, 새로 넣은 `[측정 기반 RAG 튜닝]` 하나가 “판단·검증”을
> 증명합니다. 이 대비가 “만들 줄 안다”를 “판단할 줄 안다”로 끌어올립니다.
